## Phase 3 — same-host recovery priority and Primer dispatch safety

- Per-controller atomic recovery leases publish pending/armed/verifying across workspace windows; heartbeat is independent of quota polling. Expired leases plus grace are ignored; malformed/unreadable coordination suppresses Primer while Auto Resume continues.
- Primer checks quota, active work (including pagination), and recovery priority at candidate, post-jitter, locked preflight, and immediately before dispatch. Manual Prime uses the same protection. A fresh motion interval outside the lock detects windows activated by real work after the original candidate.
- A host-authoritative atomic send journal survives independent Memento caches and restarts. Uncertain dispatch remains pending without expiry. Accepted dispatch releases the lock before completion observation; definitive unsent cancellation clears its intent.
- Lock ownership tokens, live-process checks, and stale-lock retirement fences prevent delayed holders/creators from deleting or overwriting a successor. Tiny retired lock directories are retained as fencing evidence.
- Official installed Codex protocol was generated locally without account requests: ordinaryUsageAllowed null is explicitly unavailable; thread status `idle` is supported along with legacy `inactive`.
- Validation: typecheck/compile/diff whitespace PASS; full intermediate suite PASS (96/96), including cross-window independent-cache, corrupted storage, lifecycle, short-lock, and delayed-dispatch regressions.

## Live 5h quota exhaustion/recovery evidence (user-observed; 2026-10-16)

A real Codex Remote SSH work conversation was verified from the VS Code extension Output and the user's confirmation that the resumed turn performed work. Conversation identifiers and private endpoint details are deliberately omitted from this summary.

- **PASS — first quota block:** the original work turn ended `failed / usageLimitExceeded`, with the primary 5h window at 100%; Auto Resume persisted Armed with the exact interrupted thread/turn and the backend's reset timestamp.
- **PASS — transient rate-limit read failures:** repeated failed account reads and later recovered reads preserved the Armed target; a recovered *read* alone was not confused with available usage.
- **PASS — ordinary reset confirmation:** Output contained `availability detected; confirming with an independent read in 10s`, then `confirmed quota recovery`. The original 5h reset was not an early-reset event; the separate deterministic early-availability tests remain the evidence for that path.
- **PASS — exact Remote UI continuation:** `chatgpt.conversationEditor` surfaced the original thread; the official owner was discovered; `thread-follower-start-turn accepted` appeared; and a **new** resume turn appeared on that original conversation.
- **PASS — at-most-once behavior:** one resume turn remained tracked across repeated `interrupted / error=none` history observations and intermittent quota-read failures; no repeat continuation was submitted.
- **PASS — second quota exhaustion re-arm:** the user verified the resumed task really continued executing and consumed the **next** 5h allowance before finishing. Its new turn eventually reported a structured `failed / usageLimitExceeded`. Auto Resume re-armed on **that new interrupted turn** for the next reset. Long-running `interrupted/error=none` history snapshots alone are not evidence of a stalled task.
- **NOT OBSERVED — terminal completion/Disarm:** the resumed task was not finished when quota depleted again, so this particular live run cannot exercise completed-turn Disarm. Deterministic completion/stability tests still cover it.
- **PASS — blocked Primer:** in a different (Windows Local) workspace/extension host, Primer reported Enabled and waiting for `ordinary-usage-blocked` or `contradictory-signals`; `Prime Quota Now` was safely rejected with no turn sent. This establishes quota suppression while blocked, not cross-host work-priority coordination.

Primer may be enabled on only one host per account; do not infer global Work-first precedence when work is Armed in a different host. A natural available-quota overlap remains unverified.
