## 0. Prerequisites and safety

1. Download the **codex-auto-resume-vsix** artifact from CI #142, extract the ZIP, and locate `codex-auto-resume.vsix`. Verify version `0.3.10` after install. Use that exact artifact for both Local and Remote tests.
2. Do **not** interrupt active Codex tasks or manufacture quota exhaustion just to run these checks. Perform quota recovery observation only during a genuine natural limit/reset event.
3. Inspect `Codex Auto Resume: Show Status` and `Codex Auto Resume: Show Quota Primer Status` **before changing enable settings**. If Auto Resume is currently Armed or Verifying, do not Disable: doing so clears the tracked recovery state.
4. For the same Codex account, **enable automatic Quota Primer on only one** Local/Remote extension host. **Prefer the same extension host that runs the important Auto Resume work**: host-local Work-first priority cannot see an Armed conversation on a different Local/Remote host. If active recovery is running elsewhere, disable automatic Primer here until that work is finished. Same-host multiple VS Code windows remain guarded.
5. Use a disposable Codex conversation for any deliberate prompt/IPC smoke test: the test command really sends a prompt. Avoid work conversations containing unfinished critical edits.
6. For Remote SSH, install both this extension and official `openai.chatgpt` in the **SSH remote extension host**, not only on the local Windows VS Code instance. Keep the existing known-good `http.proxy` configuration.
7. Never paste tokens, cookies, credentials, or unredacted proxy URLs into the acceptance record.

## 1. Install and basic Local smoke

- [ ] **L01 — install**: VS Code → Command Palette → `Extensions: Install from VSIX...` → choose the artifact. Confirm the installed `Codex Auto Resume` version is **0.3.10**.
- [ ] **L02 — status**: run `Codex Auto Resume: Show Status`; expected: current state is displayed without errors (Monitoring / Armed / Confirming / Verifying / Off, as applicable).
- [ ] **L03 — independent toggles**: verify `Enable` and `Enable Quota Primer` affect only their respective feature. Do this only when no genuine recovery is currently pending.
- [ ] **L04 — ordinary completion**: allow a disposable real work conversation to complete normally. Expected: Auto Resume does **not** send a continuation to a successfully completed turn.
- [ ] **L05 — manual bridge** (optional; consumes quota): in a disposable thread run `Codex Auto Resume: Test Official UI IPC Bridge`. Expected: the **same** conversation receives exactly one harmless test turn, without a new writer work thread.
- [ ] **L06 — historical Primer identity** (optional, only with no pending Primer): inspect existing Primer status, then run `Reset Quota Primer Thread`. The old dedicated Primer conversation must remain excluded from Auto Resume work discovery. This command intentionally changes the reuse target; note the old ID first.

## 2. Remote SSH smoke

- [ ] **R01 — remote install**: in the connected Remote SSH VS Code window install the same VSIX **in SSH remote**. Confirm version 0.3.10 and official `openai.chatgpt` are remote-host installed.
- [ ] **R02 — connectivity**: open `Output: Codex Auto Resume` and verify the spawned monitoring app-server can retrieve rate-limit snapshots. An occasional transient failed read is not an automatic send; repeated failed reads are a blocker.
- [ ] **R03 — proxy unchanged**: confirm the known-good effective VS Code `http.proxy` still reaches `account/rateLimits/read`. Do **not** edit proxy settings solely to run this test.
- [ ] **R04 — exact UI owner** (optional; consumes quota): with a disposable conversation run `Test Official UI IPC Bridge`. Expected: owner discovery succeeds, `thread-follower-start-turn` is accepted, and **one new turn appears in the same thread**.
- [x] **R05 — reload persistence** (PASS; user-confirmed on 2026-10-16): with no active send, reload the Remote VS Code window and recheck both status commands; historical Primer IDs and monitored thread state must not be lost. If a real Verifying attempt is underway, do not manually restart it.
- [ ] **R06 — two-window protection** (optional): on the same Remote extension host open two VS Code windows in the same workspace. Confirm both can observe existing recovery status and there is no duplicate automatic Primer/work continuation. Do not create synthetic exhaustion.

## 3. Natural quota event — observe, do not force

- [ ] **Q01 — structured quota limit**: when real work naturally fails with `usageLimitExceeded` or `rateLimitExceeded`, record the thread ID and turn ID. Auto Resume should become **Armed** without treating a separate Primer thread as work.
- [ ] **Q02 — Primer suppressed**: while quota is genuinely blocked, `Show Quota Primer Status` should remain Enabled/Waiting (if enabled), but **no Primer turn is submitted**. The work recovery has priority.
- [ ] **Q03 — early reset** (conditional): if backend quota becomes available *before* the old `resetAt`, expect `early availability detected`, a second successful read **at least 10 seconds later**, then exactly one automatic continuation. No need to wait old `resetAt + resetGrace`.
- [ ] **Q04 — normal reset** (alternative): if backend recovers at its expected time, the same two independent readings must precede one resume.
- [ ] **Q05 — temporary quota-read failure**: if a read is unavailable/contradictory, no continuation or Primer is sent on that evidence; Armed is preserved.
- [ ] **Q06 — real same-thread continuation**: official UI receives the configured Chinese continuation prompt once. The new turn belongs to the exact interrupted thread, with its original work settings (no Primer model/effort override).
- [ ] **Q07 — Verifying → Disarm**: while new work executes, `Show Status` may read Verifying (including transient `interrupted/error=none`). On `completed` it must log `resumed and disarmed` and return to Monitoring with no second continuation.
- [ ] **Q08 — manual Stop**: an unstructured `interrupted/error=none` turn by itself must not trigger an automatic continuation, even if the account quota is also blocked.

If no natural quota limit/reset occurs during acceptance, mark Q01–Q08 **NOT OBSERVED** rather than claiming PASS. Existing v0.3.9 actual Remote E2E and v0.3.10 deterministic tests are supporting evidence, not substitutes for new live observation.

- [ ] **P02 — independent monitoring**: blocked/unavailable quota suppresses sending but does not disable future polling.
